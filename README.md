# UMI 测序分子的错误吸收与共识

离线、可导入的 Python 单文件库：给定固定长度 UMI 与等长 DNA 读段（每碱基
Phred 质量 Q∈0..40），先按丰度规则把 UMI 错误节点吸收成分子簇，再在每个簇
内按独立错误模型做逐碱基 A/C/G/T 对数似然共识。

## Python 版本与依赖

- Python **3.14.7**（代码不使用 3.14 独有语法，3.10+ 亦可运行，验收环境为 3.14.7）
- **仅标准库**（`math`、`dataclasses`、`typing`），安装 Python 后无需安装任何
  其他依赖；不联网、不需要账号/密钥/数据库/中间件/云 API/Docker。

## 准确命令

```bash
python -m unittest discover -s tests -v   # 运行全部必要测试
python demo.py                            # 固定输入演示（真实计算，约 0.04 秒）
```

两条命令均在仓库根目录执行。

## 一分钟示例

```python
from umi_consensus import cluster_umis, consensus, collapse

clusters = cluster_umis({"AAA": 10, "AAC": 1, "AAG": 10})
# 排序：计数降序再字典序。AAC(1) 与两个大根距离都为 1，但只能归属首个最高根
# AAA；低丰度桥不会把 AAA 与 AAG 合并 → 2 个簇。

sequence, confidence, scores = consensus([("A", (10,)), ("A", (10,)), ("C", (40,))])
# 对数似然逐位置累加；低质量多数可被高置信少数推翻。

molecules = collapse([("AA", "AC", (30, 30)), ("AT", "AC", (20, 22))])
# 一站式：吸收 + 共识，返回 Molecule（根、成员、共识、各位置信心差）。
```

## 公开接口与数据结构

全部定义在 `umi_consensus.py`，`from umi_consensus import ...`：

| 名称 | 说明 |
|---|---|
| `Read(sequence, qualities)` | 读段：`str`（仅 A/C/G/T）与等长 `tuple[int,...]`（Q∈0..40） |
| `Record(umi, sequence, qualities)` | 带 UMI 的输入记录，字段顺序即 `(umi, sequence, qualities)` |
| `Cluster(root, members, node_counts, read_count)` | 吸收簇；成员含根，按节点排序 |
| `Molecule(root, members, node_counts, read_count, consensus, confidence, scores)` | 共识分子 |
| `ValidationError(ValueError)` | 所有非法输入；带 `index`、`field`、`message` 定位属性 |
| `BASES` | `("A","C","G","T")` |
| `LIMITS` | 接口边界常量字典（见下） |
| `cluster_umis(counts) -> tuple[Cluster,...]` | 纯函数。`Mapping[str,int]` UMI 计数 → 簇；空表返回 `()` |
| `consensus(reads)` | 纯函数。读段序列 → `(共识串, 信心差元组, 每位置四碱基 log10 似然)`；空读段抛错 |
| `collapse(records)` | 纯函数。`Record`/三元组可迭代对象 → `tuple[Molecule,...]`；空批次返回 `()` |

`Molecule.scores[pos]` 是 `{"A","C","G","T"} -> log10 似然` 字典（可能含
`-inf`，不含 NaN）；`Molecule.confidence[pos]` = 最高似然 − 次高似然。

## 吸收规则（本题精确契约）

1. 节点排序键唯一确定为 **计数降序，再 UMI 字典序升序**。
2. 处理节点 u 时，只看向排序更早的节点 v（“从大到小”方向）。u 可被 v 吸收
   当且仅当同时满足：
   - Hamming 距离恰为 **1**；
   - `count[v]` **严格大于** `count[u]`（相等计数互不为“大节点”，相等根
     永远独立——即使 `1 >= 2·1−1` 代数成立）；
   - `count[v] >= 2·count[u] − 1`。
3. 合格父节点可能不止一个；u 归属其中**排序最靠前（首个最高根）**的节点
   所在的根（沿父链追溯，根在其被处理时已固定，不会被后续节点改变）。
4. 因此低丰度桥（同时邻接两个大根的小节点）只会带着它自己的读段进入一个
   根，**两个大根永不因此合并**，也不存在事后回溯合并。

邻接通过枚举每个节点全部 3·L 个 Hamming-1 变体并查计数表得到，是**穷举
精确**的（O(n·L) 次查表），不是近似/启发式搜索。

## 共识数学模型

每位碱基独立，错误率 `p = 10**(−Q/10)`，错配在其余三个碱基上等概率：

```
P(观测=c | 真值=b) = 1 − p        若 b == c
                   = p / 3       若 b != c
```

每位置对四个候选真值累加 `log10 P`：

- 唯一最大者 → 该碱基为共识；
- 最高并列（两个及以上碱基似然严格相等，包括 Q=0 单读段时三个错配碱基
  并列）→ 输出 `N`，该位信心差精确为 `0.0`；
- Q=0 时 `p=1`，与观测一致的候选真值概率恰为 0，记为 `-inf`；若排除后
  只剩一个有限似然碱基，信心差为 `+inf`。

先按 `(位置, 观测碱基, 质量)` 做**整数计数**再求和，结果只取决于各
(碱基,质量) 的条数，与读段输入顺序无关。

## 输入上限（接口边界）

| 边界 | 值 |
|---|---|
| UMI 长度 | 1..16 |
| 读段长度 | 1..500 |
| `collapse` 单批读段条数 | ≤ 100,000 |
| `cluster_umis` 不同 UMI 节点数 | ≤ 100,000 |
| 单 UMI 计数 | 1..100,000 |
| 每碱基质量 Q | 0..40（整数） |
| 字母表 | 序列/UMI 仅 `A/C/G/T`（拒绝小写、`N`、其他字符） |

超限即抛 `ValidationError`，不静默截断或纠正。上限是接口边界；`demo.py`
为短演示，不穷举上限规模。

## 错误语义

- 所有非法输入抛 `ValidationError`（`ValueError` 子类），消息带可定位前缀
  （如 `record[1] qualities[5]: ...`），属性 `index`（批次记录下标，0 起；
  计数表场景为问题 UMI 键）与 `field`（出错字段）。
- **整数参数拒绝 bool**（`True/False` 虽是 `int` 子类也拒绝）；质量位只接受
  整数，故 `NaN/Infinity/浮点` 质量与浮点计数一律拒绝。
- `consensus([])` 拒绝（空读段组无法定义共识）；`collapse([])` 与
  `cluster_umis({})` 返回空元组（空批次是合法的零结果，语义不同）。
- 三个公开函数都是**纯函数**：不修改输入，先完整校验再计算，校验失败不
  产生任何部分结果（模块不持有跨调用状态，因此不存在有状态部分提交）。
- **搜索预算耗尽 vs 证明无解**：本算法不存在搜索预算（邻接穷举精确、归属
  在线一次完成，每个节点必然自成根或归入更早的根），也没有“无解”分支；
  因此不设此类错误。若未来引入带预算搜索，预算耗尽必须与“已证明无解”
  分开报告——本契约下两者都不会发生。

## 浮点误差口径

- `p = 10**(−Q/10)`：IEEE-754 binary64 正确舍入（≤0.5 ulp）；`log10` 由
  平台 libm 提供（典型 ≤1 ulp，41 个质量值在调用时一次性算出）。
- 每个 `(位置, 候选碱基)` 的似然和由 `math.fsum` 对**至多 82 个求和项**
  （41 个质量档 × match/mismatch 两类）正确舍入求和，最终仅一次舍入。
- 因此输出分数与数学精确值的偏差预期 ≤ 约 2 ulp（量级 ≤ 5e−16 相对）。
  测试与独立逐条累加参考比较时用 `places=12`（绝对 1e−12），该容差远松于
  实际误差但远紧于任何真实似然差，**不用于掩盖边界判定**。
- **并列判定使用精确 `==`，不使用任何容差**：数学上并列的两个碱基具有
  完全相同的求和多重集（同质量谱），经整数计数聚合与 `fsum` 得到逐位相同
  的浮点数；数学上不并列（哪怕差 1e−15）不会被判为并列。
- 信心差在并列时精确为 `0.0`；唯一非零似然时按 IEEE-754 为 `+inf`。

## 设计取舍

- 单文件、零配置，吸收与共识既可分开调用（`cluster_umis`/`consensus`）也可
  一站式 `collapse`；`collapse` 内读段按节点序、成员内按输入序参与，虽然
  分数本身与顺序无关。
- 吸收只在“处理顺序更早”的方向找父节点并立即定根，天然杜绝低丰度桥合并
  大根与任何并查集式跨簇合并；不做传递闭包扩展。
- 共识聚合到整数计数表而非逐条浮点累加：无顺序依赖、并列可精确判定、
  Q=0 的零概率事件以 `-inf` 显式表示而非下溢。
- 序列字母表只收 A/C/G/T：N 碱基、gap、插入缺失、嵌合读段均不在本题契约内。

## 已知限制（只实现本题数学子集，不宣称行业标准兼容）

- 不做双端 UMI、插入缺失、环状/分隔 UMI、链方向校正，也不实现任何具体
  行业工具（UMI-tools 等）的完整语义。
- UMI 与读段必须定长且全批等长；不支持变长。
- 错误模型为各位置独立、错配三等分的简单模型；不建模上下文相关错误率、
  PCR 重复偏倚或质量值校准。
- 共识仅输出 A/C/G/T/N，不输出 IUPAC 歧义码；似然并列超过两者时同样为 N。
- 未做大规模流式处理：输入整批驻留内存（上限 10 万条）。
